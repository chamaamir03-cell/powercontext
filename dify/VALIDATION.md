# 雨夜小店验收步骤

先按 README 启动服务、导入 DSL 并发布。无需导入知识库或预置记忆。生成式台词不要求逐字一致，检查真实旧账、状态变化和互动逻辑。

## 样例一：掌柜跨会话记仇

初始条件：选一个全新暗号，例如 `judge-rain-20261028-a`。若该暗号已使用，可先发送 `/重开`，再用新的会话继续本章。

| 步骤 | 输入或操作 | 预期表现 |
| --- | --- | --- |
| 1 | 填暗号，发送 `偷拿蓝伞` | 掌柜吐槽；状态为蓝伞“玩家拿走未还”、怨气 3、好感 0，并显示已存档 |
| 2 | 在 Dify 新建会话，填相同暗号，发送 `查看旧账` | 新 conversation_id 下仍提及蓝伞旧事；状态保持，不凭当前聊天历史猜测 |
| 3 | 发送 `归还蓝伞` | 蓝伞回店，怨气 1、好感 1；台词呼应先前的拿伞事件 |
| 4 | 发送 `送奶茶` | 好感达到 3，获得“嘴硬心软优惠券”，解锁隐藏结局 |

技术核对：在节点“PowerContext · 读旧账”查看返回的 `scope_id`、`memory_count` 与 `citations`；在写入节点查看 `memory_ref`。第二步应读到第一步真实写入的 Atomic Memory。

## 样例二：玩家隔离与重开

1. 新建会话，填写不同暗号，发送 `查看旧账`。掌柜没有前一个玩家的旧账；怨气和好感均为 0。
2. 回到原暗号，发送 `/重开`。章节加一、状态恢复初始，模型上下文不会继续引用旧章事件。
3. 新建同暗号会话继续。应延续新章，不恢复旧章的怨气。

## 样例三：服务重启后仍记得

在样例一第四步之后执行：

```bash
python3 dify/scripts/verify_restart.py
```

脚本先暂时停止本作品的 PowerContext，确认新回合返回 503 且明确 `saved=false`；再重启本作品的游戏服务与 PowerContext，等待恢复，比较 Scope、事件、物品、关系与奖励。数据应与中断前相同。随后在 Dify 新会话中使用原暗号继续聊天。

## 自动验收与证据

`scripts/verify_app.py` 会生成独立随机暗号，通过已发布 Dify 的 `/v1/chat-messages` API 完整执行拿伞、新会话回忆、还伞、奶茶、隐藏结局和其他玩家隔离，记录真实回答、会话 ID、耗时及 PowerContext 引用。

`scripts/verify_restart.py` 在这份实际结果上追加记忆服务故障处理与重启持久化验证。

`scripts/verify_memory.py` 仅用于存储组件集成检查，固定台词已明确标注为非模型生成，不能替代完整 Dify 验收。

`tests/test_game.py` 检查重复提交、并发覆盖、玩家隔离、重开、模型未完成不落库、存储失败不假装成功、重复送礼及确定的结局规则。

实际运行证据在 `evidence/` 中归档，以文件中的测试类型和时间为准；预期行为不冒充实际结果。
