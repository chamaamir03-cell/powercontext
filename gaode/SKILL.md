# 周边去哪儿

完成单轮周边推荐。仅使用评测环境已提供的高德工具；工具名称、参数类型和返回结构以实际定义为准。模型、运行环境、工具和 API Key 由平台配置。

## 1. 理解需求

- 提取城市、起点、地点类型、步行时间上限 T、数量、硬性限制和排序偏好。推荐数量 N 为用户要求与 3 中的较小值，未指定时为 3；没有时间限制时不自行添加。
- 直接使用给定起点坐标，保持高德要求的 `经度,纬度` 顺序，不改用 IP 定位或根据名称重新定位。输入足够时直接查询；缺少必要起点或存在影响执行的矛盾时才澄清。
- “不超过 T 分钟、T 分钟内”按原始路线秒数 `duration <= 60 × T` 判断；“少于”按严格小于判断。保留用户的类型、区域、距离、价格等明确硬性条件。

## 2. 搜索一个小批次

- 使用周边搜索：`location=原始起点`，`keywords=地点类型或明确品类`。例如“想喝咖啡”检索“咖啡馆”；不把时间和推荐数量混进关键词。多个可接受品类可使用工具支持的组合检索方式，或在补搜时检索另一品类。
- 用户指定搜索半径时遵守该范围；否则，有 T 时可先按约 `100 × T` 米召回，无 T 时可先搜 2000 米，均遵守工具支持范围。搜索半径和搜索距离不能证明步行可达。
- 根据返回的名称、类型和城市筛除明显不符的地点，按 POI ID 去重；无 ID 时结合名称、地址、坐标去重。同品牌不同分店分别保留。
- 优先选择搜索返回中匹配、较近且有有效坐标的 N 个候选作为首批。搜索距离只用于选择候选，不作为最终步行距离或排序依据。保留原始名称和地址；地址为空时标注“高德未返回详细地址”，不编造门牌或坐标。

## 3. 核验步行路线

- 对首批候选查询步行路线：每次 `origin` 都是同一原始起点，`destination` 为对应 POI 坐标，各地点互为独立备选，不串成多站行程。环境支持并行工具调用时，可同时查询本批互不依赖的路线。
- 从成功返回的完整步行方案读取总距离和总时间，并与对应 POI 关联。高德常规单位为米和秒；当前工具另有说明时按其单位转换。数值字符串先转为数值，只接受有限、非负的总距离和总耗时，不取单段 steps 的数据，不将缺失值、空字符串或失败结果当成 0。
- 多方案时先过滤时间、距离等路线硬限制，再按“近一点”选距离最短的合格方案，按“快一点”或未指定偏好选耗时最短的合格方案。距离和时间取自同一方案。
- 按未舍入的秒数过滤：900 秒满足“不超过 15 分钟”，901 秒不满足。没有有效步行总距离和总耗时的地点不进入推荐，禁止用直线距离、搜索距离、经验步速或其他交通方式代替。

## 4. 按需补查并及时结束

- 首批核验完成后，已获得 N 个满足硬性条件的地点就排序回答，不为了扩大候选池继续查询。
- 不足 N 个时，优先核验已有搜索结果中的新候选，逐个补足。已有候选不够时才补搜一次，可换同义品类或扩大未被用户限定的半径；始终保留步行时间及其他硬性限制。
- 全流程最多 2 次地点搜索、5 次步行路线调用，重试计入对应上限；不要求把额度用完。平台有更严格预算时遵守平台预算，只输出成功核验的结果。
- 超时、限流或临时错误，全流程最多重试一次；认证、权限或明确配置错误不重复重试。单个地点无可用方案只排除该候选，不视为服务故障；同一必要服务持续报错时结束并说明，避免无效补搜。

## 5. 筛选、排序与回答

- 推荐仅包含类型和明确硬性条件符合、路线有效的地点。无法核实某项必须条件时，不将该地点列为满足全部条件的推荐，并说明限制。
- “优先近一点”按已核验的步行总距离升序，同距离按耗时；“最快到”按总耗时升序，同耗时按距离；未指定时优先耗时较短。只比较已核验候选，不宣称绝对最近。
- 安静、排队、当前营业、消费和评分等仅依据实际返回信息描述；无依据时标注“未核实”，不能从品牌或名称推断。软偏好未核实不等于类型或路线不合格，但必须说明限制。
- 用一句话说明起点、主要条件和排序方式，再给列表或下表，最多 N 行；每条理由只写一句有数据依据的类型匹配或路线优势。

| --- | --- | --- | --- | --- |

- 使用原始 POI 名称并保留分店名，地址照实填写；距离用米，时间由原始秒数转成分、秒，说明为路线预计值。例如 845 秒写“约 14 分 5 秒”，不向下取整掩盖超时。
- 不足数量时说明“本次查询仅核实到 X 个符合条件的地点”；成功查询但无合格结果，与搜索失败或路线未核实分别说明。查询失败不等于附近没有地点，某条路线失败不等于该地点不可步行到达。
- 零结果时不编造地点，可建议放宽时间、范围或类型，但不擅自放宽。工具未提供或配置失败时如实说明。最终只给推荐与必要说明，无需 JSON、调用日志或内部过程。

输出前确认：每行 POI 与路线一一对应、原始数据满足硬性条件、数量和排序正确、未核实信息已说明。
